- 同一文档也明确存在 approximate="tanh" 分支；没有依据把此项修复扩展成所有 GELU 算子或所有后端的默认变化。

二、BF16 checkout
发现路径：上述入口 → CPU → FAQ → “Which `dtype` should be used?”。
文件：/Users/luke/Documents/Codex/2026-10-27/chu/work/vllm-main-bf16/docs/getting_started/installation/cpu.md

证据与准确行号：
- :159 小节标题：“### Which `dtype` should be used?”
- :161：“Currently, vLLM CPU uses model default settings as `dtype`.”
- :163：“software conversion from `float32` to `bfloat16` uses round-to-nearest-even and preserves NaNs as canonical quiet NaNs.”
- :163：“Software conversion is selected automatically when a CPU kernel needs it, including when native vector BF16 conversion is unavailable”
- :163：“no additional CLI option or environment variable enables this rounding behavior.”
- :163：“The model's default `dtype` is unchanged.”

结论：
- RISC-V 软件 float32 → bfloat16 转换使用 round-to-nearest-even（就近舍入，正中间取偶），NaN 规范化为 canonical quiet NaN。
- CPU kernel 需要该软件转换时自动选择，包括原生向量 BF16 转换不可用的情况；无需额外 CLI 参数或环境变量启用该舍入规则。
- 该修复不改变模型默认 dtype，也不等同于自动把所有模型改为 BF16。
可回答性：全部问题均可仅凭上述用户文档回答。

三、OpenMP checkout
发现路径：上述入口 → CPU → FAQ → “How to decide `VLLM_CPU_OMP_THREADS_BIND`?”；变量取值可在同页“Related runtime environment variables”查到。
文件：/Users/luke/Documents/Codex/2026-10-27/chu/work/vllm-main-openmp/docs/getting_started/installation/cpu.md

证据与准确行号：
- :257 小节标题：“### How to decide `VLLM_CPU_OMP_THREADS_BIND`?”
- :259：“On Linux, including RISC-V, vLLM adds PyTorch's bundled `libgomp` to `LD_PRELOAD` before spawning CPU workers when it is available.”
- :259：“An existing OpenMP runtime in `LD_PRELOAD` is preserved”
- :259：“source or distribution builds of PyTorch without a bundled `libgomp` use their configured runtime.”
- :261：“Default `auto` thread-binding is recommended for most cases.”
- :152 变量可设 CPU id 列表、“`auto` (by default)” 或 “`nobind`”；nobind “disable[s] binding to individual CPU cores and [inherits] user-defined OpenMP variables”。
- :152：“If set to `nobind`, the number of OpenMP threads is determined by the standard `OMP_NUM_THREADS` environment variable.”

结论：
- Linux（明确包括 RISC-V）在 spawn CPU workers 前，若 PyTorch bundled libgomp 可用，会自动加入 LD_PRELOAD。
- 用户 LD_PRELOAD 中已有的 OpenMP runtime 保留。
- PyTorch 源码或发行版构建若没有 bundled libgomp，则使用它们已配置的 runtime。
- 默认推荐 auto 绑定；若用户希望关闭逐核绑定并沿用自定义 OpenMP 变量，同页记载了 nobind 和 OMP_NUM_THREADS。
- 文档对“已有 preload”的明确保证限定为已有 OpenMP runtime；没有逐项解释任意非 OpenMP preload 的组合细节，不能从这段文档额外断言细节。
可回答性：任务所问 bundled OpenMP、已有 OpenMP preload、无 bundled library 三种情况均已覆盖。
