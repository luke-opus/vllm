https://luke-opus.github.io/vllm/64079-main/getting_started/installation/cpu/?h=round+nearest+even#which-dtype-should-be-used
Answer from this FAQ: RISC-V software float32-to-bfloat16 conversion rounds to nearest even and keeps NaNs as canonical quiet NaNs. It is selected automatically when a CPU kernel needs it, including when native vector BF16 conversion is unavailable. It does not need an enabling CLI option/environment variable and does not change the model's default dtype. The surrounding FAQ still says CPU uses model default dtype settings and recommends an explicit bfloat16 choice if float16 performance/accuracy causes problems.
Short excerpts: "round-to-nearest-even"; "canonical quiet NaNs"; "The model's default dtype is unchanged."
