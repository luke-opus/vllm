1. Design Fit
-------------
1.1 Core impact: small targeted correctness/policy changes; no scheduler,
model-runner, public interface, new backend, or synchronization changes.

1.2 Reuse: ERF expands the existing activation suite. BF16 uses the shared
production conversion helper, an existing operator regression, and a small new
compiled-header test because activation outputs cannot cover all NaN/tie/overflow
bit cases. OpenMP adds RISCV to the existing Linux policy and extends the existing
platform suite; it does not add another preload implementation.

1.3 Complexity: each production-code change is under 50 lines. The 72-line BF16
fixture compiles the actual header, with 18 independent expected bit patterns,
per-module temporary storage, and checked compiler execution. It introduces no
runtime package dependency. Requiring a working C++20 compiler is a test/runtime
environment constraint, not something hidden by a skip.

1.4 Correctness, compatibility, and precise claims:
  #64078: vfsgnj defines every active output lane in both FP32 vector erf methods
  and copies the input sign, including negative zero. It removes dependence on
  masked-off lane contents. The exact and tanh public operator paths share the
  existing deterministic regression setup. This is not a new GELU mode or a
  performance claim. A physical implementation may choose undisturbed agnostic
  lanes; a native base run need not reproduce the QEMU all-ones NaNs. Preserve
  native base results and require fixed numerical/special-value checks, without
  manufacturing a hardware failure. Changed-path real-model coverage remains
  unproved; a dense model using Torch GELU is not ERF coverage.

  #64079: finite software FP32-to-BF16 conversion uses round-to-nearest-even;
  FP32 NaNs become canonical positive quiet BF16 NaNs. NaN sign/payload retention
  is not promised. All helper users, including scalar fallback users beyond RVV,
  get this behavior, so output changes are expected and shared-path compatibility
  matters. The SiLU test distinguishes 0x3d87 truncation from 0x3d88 rounding;
  the compiled-header cases cover signed zero, infinities, small-payload/negative
  NaNs, both tie parities/signs, subnormals and finite overflow. The claim is the
  conversion contract, not end-to-end accuracy improvement or logprob equality.

  #64080: RISC-V uses the existing bundled-libgomp search and preload policy on
  Linux. Existing OpenMP preload choices and absent bundled libraries remain
  respected. Real VllmConfig/DeviceConfig construction and the CpuPlatform entry
  point are used; only external OS/architecture/affinity/Torch-file inputs are
  simulated in the unit test. Loading both GOMP and LLVM in prior actual Linux
  runs means no conflict-elimination or throughput claim is justified.

1.5 Tradeoffs: no measured speedup claimed and no new steady-state device/host
synchronization. VLLM_GPU_SYNC_CHECK is not applicable to these CPU-only changes.
BF16 intentionally changes outputs. OpenMP alters child startup environment;
multi-thread, NUMA, full-server, and physical-machine behavior remain separate
coverage gaps. ERF and BF16 are independently scoped, so neither PR alone claims
to fix the other's bug.

1.6 MRV2: no model-runner code is changed. Pinned main introduces a new default
CPU MRV2 path; old-model evidence cannot certify this integration. New runtime
validation must identify the actual main source, complete DSO, and runner used.
