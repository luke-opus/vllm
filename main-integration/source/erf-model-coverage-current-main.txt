2. That custom op registers fused_experts_op at fused_moe.py:1601-1605;
   the implementation calls fused_experts_impl (:1540, :1729), which invokes
   apply_moe_activation at :1889-1891 without valid_token_counts.
3. The actual unmasked GELU_NO_MUL branch is activation.py:398-399:
   output.copy_(F.gelu(input)). This is PyTorch's GELU, not vLLM's RVV er().
   The same file's _CUSTOM_OP_NAMES entry at :97 says gelu_and_mul, but that
   symbolic name table does not replace the concrete branch just traced.
4. Independently, CPUUnquantizedExperts rejects no-act-and-mul configurations
   at cpu_moe.py:227-228 and only lists gated GELU at :231-237. Its C++ path
   parses the string at cpu_fused_moe.cpp:704. get_act_type accepts only silu,
   swigluoai, gelu, gelu_tanh; gelu_no_mul reaches the error at lines 38-39.
   Only gated gelu selects GeluAndMul, then apply_gated_act:201-202 calls
   gelu_and_mul, whose line 141 invokes FP32Vec16.er(). On RVV this is the
   implementation in cpu_types_riscv_impl.hpp:842.
